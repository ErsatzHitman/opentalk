## Pill surface material (liquid glass)
Implements the `liquid-glass` skill for a layered window (no DWM backdrop is available): `src/daemon/pill/glass.rs` (pure) and `capture.rs` (Win32).
- Surfaces: pill capsule/circle, the fused cancel bud, the app-icon bubble (a glass circle, same recipe, same height as the pill), the tooltip (menu tier) and the error card (modal tier). The logo, waveform bars, cancel glyph, divider, hover gradient and text are drawn on top, unchanged.
- Backdrop: the screen rect under the window plus a refraction margin (`0.12 * monitor size`, capped at 96 logical px, clipped to the monitor) is copied with `BitBlt` from the screen DC, box-averaged into 3 px cells, frosted (3-pass box blur ~ gaussian sigma 10 logical px, `saturate(125%)`) and sampled bilinearly (edges clamp).
- Refraction: the skill's field verbatim (`GLASS_PRESET`: edge 0.015 / rim 0.028 / base 0.05, distances 0.5 / 1.7 / 0.2, corner boost 0.06, ripple 0.26, **warp off**), signed rounded-rect `distPx`, texcoord-space normal, `pageW x pageH` = the pill's monitor in logical px. Each glass pixel samples the frosted backdrop at its displaced position. The displacement map of an exact rounded box is baked once per (size, radius, monitor size, scale, sub-pixel phase) and reused.
- Material on top (tokens of `liquid-glass.css`): frost layer (the modal tier, stronger for the 36 px pill: white 56 % in light mode, near-black 69 % in dark mode; the pill follows the app theme), tint gradient white -> 70 % grey at 6 % (11 % while hovered), three inset rim highlights (top 1 px at 0.55 / 0.50, hairline 0.12 / 0.10, bottom 0.06), 1 px border (`rgba(30,33,45,.12)` / `rgba(255,255,255,.08)`; x0.6 in the processing / thinking / unavailable states, as the old `border/60`), drop shadow (the skill's `0 10px 30px` scaled to the 12 px the window leaves around the pill: `0 3px 9px` light, `0 4px 10px` dark; lifted while hovered).
- Legibility (unit-tested): foreground against the glass is >= 4.5:1 over the waveform lane and the logo for pure white, pure black and a busy stripe/noise backdrop, in both themes.
- Cost (PLAN section 1 stays binding: an idle daemon runs no timers and does not poll): nothing is captured while the window is hidden. The copy (`BitBlt` waits for the compositor, ~5 to 25 ms wall but <0.5 ms CPU) and the cell hash / frost run on a worker thread (`pill-glass`, started on the first request, blocked on a channel while idle, joined on exit) so the UI thread never waits: it only posts a request (~10 us) and installs a finished picture on `WM_APP_GLASS`. A periodic USER timer on the pill window requests a capture every 125 ms while the pointer is on the pill or it is dragged, and every 250 ms while recording, preparing, thinking, unavailable (mic reconnecting) or animating; it is **killed whenever the pill rests** (the idle circle, and an error card counting down). The resting circle and the error card are refreshed on events only, so their frost can be slightly stale: on show (the kept picture is placed at once and refreshed within a frame or two), on a state / size / dock / scale / monitor / position change (rate-limited to one request per 100 ms, one in flight; an owed request becomes a one-shot timer that fires once and is killed), on hover (the 125 ms rate runs while the pointer is on the pill), on `WM_SETTINGCHANGE` (wallpaper, colours), and through out-of-context WinEvent hooks (`SetWinEventHook`, `WINEVENT_OUTOFCONTEXT | WINEVENT_SKIPOWNPROCESS`, no DLL injection; installed while the window is shown, removed when it hides) for `EVENT_SYSTEM_FOREGROUND`, `EVENT_SYSTEM_MOVESIZEEND` and `EVENT_SYSTEM_MINIMIZESTART`/`END`: another window coming to the front, finishing a move / resize, or being minimised or restored posts `WM_APP_SCREEN_EVENT`, which arms a one-shot 400 ms settle timer (the changed window has finished animating; a burst of events costs one capture). These events come at human pace; the chatty `EVENT_OBJECT_LOCATIONCHANGE` / `SHOW` / `HIDE` (carets, cursors, tooltips) are not hooked, so content that scrolls or redraws under a resting circle without a window event is picked up only at the next event or hover. A lost `WM_APP_GLASS` post (full queue) is recovered by the next timer tick, settle timer or screen event. A capture whose cell hash (colours >> 2, so grain and dithering do not count) is unchanged recomposes nothing. Steady recording frames still redraw only the waveform lane: the glass lives in the cached base layer, which is rebuilt only when the backdrop picture changes. The error card uses a stronger frost (white 82 % / near-black 95 %) because its muted text is smaller than the pill's glyphs.
- Memory and CPU budget (unit-tested bounds, `capture_buffers_are_small_and_bounded`, `baked_displacement_cache_is_bounded_in_slots_and_bytes`; numbers below are an optimised build run under Wine on a 4-core Linux host, not a Windows desktop):
  - Buffers: the capture DIB is (208 + 2 x 96) x (120 + 2 x 96) logical px x 4 B = 0.5 MB at 1x, 1.1 MB at 1.5x, 2.0 MB at 2x, and is given back after every event-driven copy (whenever no periodic timer runs) and when the window hides. The cell grid + frost working set is ~0.3 MB (transient, on the worker); the kept frosted picture is ~40 KB. The baked displacement maps are capped at 8 maps / 2 MiB in all (a 98x36 capsule is 0.13 MB at 2x, the 442 px error card 1.5 MB), least recently used first. Expected steady cost on top of the base daemon: ~2.5 MB at 1x, ~5 MB at 2x while recording; ~1.5 MB while resting.
  - Per capture (1x / 2x): screen copy 0.4 / 1.5 ms wall (Xvfb; not measured on Windows, where `BitBlt` also waits for the compositor), cell average + hash 0.3 / 0.4 ms (reads a quarter of the pixels), frost 0.4 / 0.4 ms (only when the picture changed). A static screen therefore costs ~0.3 % (1x) to ~0.8 % (2x) of one core while recording at 4 Hz and nothing while resting (one capture per screen event); a constantly changing backdrop (video) adds a base-layer rebuild of 1.0 / 4.0 ms per capture (~1.1 % / ~2.5 % of one core, which is 0.1 to 0.3 % of an 8-core machine, the unit `bench.ps1` reports as `CpuPctAll`). Steady 60 fps recording frames cost 0.02 / 0.07 ms each (waveform lane only, unchanged from before the glass). The error card's glass is rebuilt in 7 / 31 ms when a capture finds a new picture under it (it is captured as it appears and then only on screen events).
  - The measurements are printed by `cargo test -- --nocapture capture_cost glass_frame_cost glass_paint_cost` and, on a real desktop, by the ignored `desktop_pill_capture_cost`.
- Capture exclusion: the window calls `SetWindowDisplayAffinity(WDA_EXCLUDEFROMCAPTURE)` so the screen copy never contains the pill. **Side effect: the pill (and bubble, tooltip, error card) is invisible to screenshots, screen recordings and screen sharing.** The flag needs Windows 10 2004; where it is refused, or when a capture fails (secure desktop, locked session), nothing is captured and the glass is frosted over a flat neutral backdrop (light `#d9dce3`, dark `#30333a`) - never garbage. The exclusion itself (that `BitBlt` with `CAPTUREBLT` honours the flag) is checked by the ignored `desktop_pill_capture_excludes_the_pill`, which needs an unlocked, composed desktop and skips itself otherwise.
- Goldens: `--render-pill <state> <t_ms> out.png [--dark] [--composite] [--upscale N] --backdrop white|black|gradient|busy-text|path.png` renders over a fixture (`tests/fixtures/pill_backdrops/`, the bottom-right 640x360 of a 1920x1080 screen with a 40 px taskbar, window docked as the daemon would); without `--backdrop` the neutral backdrop is used, so every render is deterministic.
- Known limits: the cancel cross is drawn in `muted-fg` (unchanged) and reaches only ~2.4:1 against the frosted glass over a pure-black backdrop in light mode (and ~2.2:1 over pure white in dark mode); it is a 13 px glyph that turns `fg` under the pointer, and the waveform, logo and all text meet 4.5:1. The error cards' goldens contain GDI text and are only valid on a Windows machine (Wine lacks Segoe UI); they are not regenerated from Wine.
- Pictures: contact sheets of the pill states over the busy-text and gradient fixtures (light left, dark right; idle, recording, thinking, cancel, tooltip, with the app-icon bubble) are in `docs/screenshots/pill-glass/` (`pill-over-busy-text.png`, `pill-over-gradient.png`, `error-card-over-backdrops.png`), rendered with `--composite`; the error card text there is Wine's fallback font.
- Superseded tokens: `surface-0/1/3`, `popover`, `border` and `border-hover` no longer paint any fill or border (the glass does); `fg` and `muted-fg` still colour the logo, bars, cancel glyph, text and the Retry button.
